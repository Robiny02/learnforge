背景 / 动机

Phase 1 已落地统一结果契约 AgentResult。Phase 2 在其上定义三类可插拔 Handler 的接口， 为后续“新增能力不必改 Manager 主循环”打地基。本阶段只给接口与空注册表，不接入任何现有 Agent （行为零变化）。同时按你的要求，把未来要清理 / 收敛的文件统一打标记。

变更内容

  • 三个 Protocol（contracts/handlers.py，runtime_checkable）：
    • CapabilityHandler —— capability + run(request, context) → AgentResult。 QA/Diagnosis/Planning/Mock/EvidenceResearch 的统一执行面。
    • EvidenceProviderHandler —— source_type + fetch(query, targets, context) → List[EvidenceRef]。 resume/repo/file/attachment/retrieval 的只读读取面（回指针+片段，非全文）。
    • ToolHandler —— name + effect + __call__(arguments) → ToolResult。 file/mcp/local 工具的统一调用面。
  • 空注册表 HandlerRegistry（orchestration/handler_registry.py）： register/get/has/capabilities，容忍 str 或 Capability，未知值安全返回 None。 进程内单例 HANDLER_REGISTRY 默认空、未接入 Manager。
  • 从 learnforge.contracts 追加导出三个协议（加法）。
分层取舍：协议放 domain（contracts/），其中 ToolHandler 对 ToolResult 的引用走 TYPE_CHECKING（运行期不导入，无 contracts→tools 循环）。ToolResult 将在 Phase 6 提升进 domain，届时移除该临时引用。
