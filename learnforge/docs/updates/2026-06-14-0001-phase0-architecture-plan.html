轻量 DDD + 可插拔 Handler 重构方案

Phase 0 docs risk · none

#0001 · 2026-06-14 · 分支 feat/mock-answer-quality · 基线 commit 4f11c2f

背景 / 动机

LearnForge 已是 orchestrator + tools 架构，但随能力增多，几处边界开始混乱： Manager 成了上帝对象、新增能力必须改 _dispatch_impl 的硬编码 if/elif、证据/产物/控制信号 靠无类型的 context / meta dict 传递、工具注册表命名重叠。本次产出一份 轻量 DDD + 可插拔 Handler 的重构方案，先统一接口与边界，不做企业级重分层。

变更内容

新增架构文档 docs/architecture/refactor-plan.md，含：

  • 边界审查：识别 5 处最混乱边界（三 registry + 两 descriptor 命名地狱、Manager 上帝对象、 路由散在 4 处、ResponsePayload.result 不透明 + 旁路 dict、并行轨道未隔离）。
  • 关键发现：EvidenceResearchAgent + Manager.gather_evidence 已完整实现， 但除测试外从未被真实调用 —— 统一只读证据 worker 是半成品（Phase 5 补接）。
  • 三类可插拔 Handler：CapabilityHandler（QA/Diagnosis/Planning/Mock/Evidence）、 EvidenceProviderHandler（resume/repo/file/attachment/retrieval）、 ToolHandler（file/mcp/local 统一注册 + 权限闸）。
  • 统一 AgentResult：让 Manager 只读 status / payload / evidence_refs / artifact_refs / next_request / reason 即可编排。
  • 8 阶段迁移计划（Phase 0–7）+ 每阶段测试 + 风险/回滚表。

涉及文件

测试

纯文档，无代码变更，无需测试。现有 pytest 基线不受影响。

影响 / 风险 / 回滚

零代码、零行为影响。回滚 = 删除该文档。

重构原则（贯穿全程）：不大爆炸、不先搬文件、不改业务行为、不破坏测试、子 Agent 不互调、 Diagnosis 不提权、Planning 不直写 path、Evidence 本体不进 Conversation State、不引入 shell/exec。
