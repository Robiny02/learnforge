背景 / 动机

这是第一个真正动 Manager 的阶段。把 _dispatch_impl 里硬编码的 if agent=="qa"/"diagnosis"/"planning"/"mock" 四段派发（边界 B2 的核心痛点），改成经 Phase 2 的 HandlerRegistry 分发——新增能力 = 注册一个 handler，不再改 Manager 主循环。 要求行为字节级不变。

变更内容

  • 新增 orchestration/capability_handlers.py：四个 CapabilityHandler （QA/Diagnosis/Planning/Mock），把对应分支的全部逻辑与副作用原样搬入 （emit_qa_signal / persist_diagnosis / remember / 简历子路由 / status 映射），产 AgentResult。
  • ManagerAgent 构造时 build_default_handlers(self) 注册四能力到实例私有注册表 （非全局单例，避免多 Manager 串扰）。
  • _dispatch_impl 从 ~60 行 if/elif 缩成 10 行查表分发： handler.run(...).to_response_payload()，对下游 ResponsePayload 字节级等价。
  • 顺手清掉因此空出的 4 个 import（QAInput / PlanningInput / PlanMode / DiagnosisResult）。 manager.py 1316 → 1269 行。
唯一写者不变：handler 只读子 agent + 调用 Manager 既有的写/记忆/埋点方法，自己不落 mastery/path。 Diagnosis 仍严格只读（test_diagnosis_is_read_only 守护）。
