EvidenceProvider 收敛 + 接通 need_evidence 回路

Phase 4 + 5 feature risk · med tests · green

#0006 · 2026-06-14 · 分支 feat/mock-answer-quality · 基线 commit 4f11c2f

背景 / 动机

两件事一起做：① Phase 4 把分散的证据读取路径收敛成可插拔 provider；② Phase 5 把建好却悬空的 EvidenceResearchAgent（此前仅测试调用）真正接进诊断流程—— Diagnosis 信号不足时回 need_evidence，由 Manager 调统一只读证据 worker 补证据再复诊， 而不是让 Diagnosis 自己去读一堆 source。

Phase 4 — EvidenceProvider 收敛

  • 新增 agents/evidence/providers.py：四个实现 EvidenceProviderHandler 协议的 provider （File / Repo / Attachment / Resume），把原 EvidenceResearchAgent._collect_* 的逐源逻辑**原样搬入**。
  • EvidenceResearchAgent.run() 改为按 source_type 编排 provider： provider.fetch(query, targets, ctx) → ProviderResult(evidence_refs + source_refs)， 合并进 EvidencePacket。新增证据源 = 加一个 provider，不改 worker 主循环。
  • 细化 Phase 2 协议：fetch 返回 ProviderResult（新契约，含 source 勘探记录）， 而非裸 List[EvidenceRef]。
  • provider 经 agent.call_tool(...) 走权限门调底层只读工具——严格只读不变量保持。

Phase 5 — 接通 need_evidence 回路

  • DiagnosisInput 加可选 evidence_context（补来的只读证据摘要，进 ReAct 接地； 确定性兜底不据此编造掌握度）。
  • DiagnosisCapabilityHandler：弱点诊断 confidence < 0.5 且非复合、 未补过证据 → 回 AgentResult.next_request = need_evidence（带 query + source_types）， 且此时不落库（避免一次逻辑诊断写两条快照）。
  • Manager._dispatch_impl：收到 need_evidence → _fulfill_need_evidence 调 gather_evidence([attachment, resume]) → attach_evidence_to_context 注入 context["evidence_artifact"] → 置 _evidence_gathered 防重入 → 复跑一次。
只读 & 语义保持：补证据 + 复诊全程不写 mastery/path（test_diagnosis_is_read_only + 新测试守护）； 强信号（seeded_db conf≈0.55）与复合"准备面试"流程不触发——黄金回归与 §5.6 语义不变。 证据本体不进 Conversation State——只注入 artifact 摘要 + 指针。
