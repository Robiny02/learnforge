核心契约：AgentResult / ArtifactRef / NextRequest

Phase 1 contracts risk · low tests · green

#0002 · 2026-06-14 · 分支 feat/mock-answer-quality · 基线 commit 4f11c2f

背景 / 动机

当前子 Agent 的回收结果散在三处：ResponsePayload.result: Dict（不透明结论）、Manager 主循环里的 context grab-bag（context["diagnosis"] / ["evidence_artifact"]）、以及 meta grab-bag（meta["notion_url"] / ["path_committed"] / ["suggest_mock"]…）。本次纯加法引入统一的类型化结果契约，为后续 Phase 3 把 Manager 的硬编码派发改成注册表分发打地基。

变更内容

  • AgentResult —— 泛化 ResponsePayload，字段： status / confidence / payload / evidence_refs / artifact_refs / next_request / reason / cost_usd。 让 Manager 只读这几个字段即可编排，不必知道底下是 qa 还是 mock。
  • ArtifactRef + ArtifactKind —— 类型化“产物指针”，取代散落的 meta[...]（notion / report / plan_image / committed_path / mock_session / diagnosis_report…）。
  • NextRequest + NextRequestKind —— 结构化“下一步诉求” （need_evidence / need_clarification / suggest_capability）。 这是协作铁律的落点：Diagnosis 证据不足时返回 need_evidence，而不是自己读 source 或 spawn。
  • 双向 adapter from_response_payload / to_response_payload —— 供渐进迁移； ResponsePayload 原样保留，仍是线上类型。
零调用方改动：未触碰 Manager、各子 Agent、tools、skills。只新增文件 + 一处 __init__ 导出。
