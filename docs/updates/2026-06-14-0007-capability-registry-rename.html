命名收敛：MCP_REGISTRY → CAPABILITY_REGISTRY

Phase 6 refactor risk · low tests · green

#0007 · 2026-06-14 · 分支 feat/mock-answer-quality · 基线 commit 4f11c2f

背景 / 动机

收掉边界 B1 命名地狱的最后一块：tools/registry.py 里的 MCP_REGISTRY/MCPRegistry 其实是内部能力权限目录（工具名 → ToolSpec + 权限校验），与外部 MCP server（tools/mcp/） 毫无关系，却顶着 MCP 的名字，读代码极易误解。本次更名为 CAPABILITY_REGISTRY/CapabilityRegistry， 旧名保留为兼容别名。

变更内容

  • tools/registry.py：MCPRegistry → CapabilityRegistry、 MCP_REGISTRY → CAPABILITY_REGISTRY，更新模块文档说明它是“内部能力权限目录、与外部 MCP 无关”。
  • 文件末尾保留兼容别名 MCPRegistry = CapabilityRegistry、 MCP_REGISTRY = CAPABILITY_REGISTRY（向后兼容历史 import）。
  • 第一方代码全部改指新名：agents/base.py、skills/registry.py、 tools/collection.py、tools/__init__.py（再导出新名 + 兼容别名）+ 3 个测试文件。
行为零变化：别名 is 同一对象（MCP_REGISTRY is CAPABILITY_REGISTRY），任何仍用旧名的外部/历史代码继续可用。

同时评估并“留下”的两项

Phase 6 还标过两处，复核后改判为保留（去掉 LF-CLEANUP 标记）：

  • tools/runtime.py::DEFAULT_TOOL_REGISTRY：看似 facade，实为默认工具 handler 的 注册落点（_register_defaults 把 diagnosis/file/evidence 工具注册进它 → TOOLS）， 是 bootstrap 入口而非死代码 → 保留。
  • graph/main_graph.py：python -m learnforge.graph.main_graph 是 CLAUDE.md 记录的 smoke 入口，合法别名 → 保留。

至此源码内 LF-CLEANUP 标记全部清零（要么已清理，要么评估后明确保留）。

涉及文件

～ tools/registry.py（更名 + 兼容别名 + 文档）
～ tools/__init__.py（导出新名 + 别名）、tools/collection.py、agents/base.py、skills/registry.py（改指新名）

测试
