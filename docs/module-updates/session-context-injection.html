0 · 头条：被丢弃的接线

关键发现

会话记忆机制完整实现，但产物在送进 QA/diagnosis/planning 之前被丢弃。 manager_plan 把它读进 state["conversation_summary"] 后， execute_dynamic / dispatch / QAInput 都不消费它——而记忆面板还在谎报「已注入」。

后果：优化 pinned 保留 / summary 稳定性 / 重要性判断，在补好这条接线前对回答质量毫无影响。 接线才是承重修复——这正是阶段一只做接线的原因。

# 修复前——会话记忆是一段「死状态」
manager_plan   begin_memory_turn() → state["conversation_summary"]
     │
     ▼
manager_execute → execute_dynamic(user_input, trace_id)
     │   context = {"composite","trace_id"}        ← 没带会话记忆
     ▼
_dispatch_impl → qa.run(QAInput(question=user_input))   ← QAInput 无 session 字段
     │
     ▼  pinned/summary/recent 被丢弃；MEMORY_LOG 却记「注入会话摘要」（幻影）


# 修复后——单一真值 build_session_context 贯穿注入与观测
execute_dynamic(user_input, trace_id, session_id)
     │   sctx = build_session_context(session_id)   ← 有界装配
     │   context["session_context"] = sctx.render() + MEMORY_LOG 记真实 INJECT
     ▼
_dispatch_impl → qa.run(QAInput(…, session_context))
     ▼
Synthesizer._session_block() → assemble_prompt(session=…) → 进入 LLM prompt 的 volatile 尾部

1 · 装配什么：有界的 session_context（5 段）

新增 memory/session_context.py——单一真值装配器：execute_dynamic 注入用它， 记忆面板 prompt_load_overview 报告也用它，两边不再各算一套。纯读、离线安全、Manager 不写。

  • 注入 assembler 的 volatile 尾部（缓存边界之后，不破坏 KV-cache prefix §6c）

learnforge/orchestration/manager.py · build_session_context（真实注入点）
def build_session_context(self, session_id):
    sctx = _build(session_id, db_path=self._db_path)
    if sctx.is_empty(): return ""          # 无历史 → 不渲染、不谎报注入
    MEMORY_LOG.record(INJECT, "注入会话上下文",
        f"{sctx.total_tokens()} tokens / {len(sctx.sections)} 段…", count=1)
    return sctx.render()                       # 整体再过一道全局预算天花板

4 · 可观测性诚实化（§7）

  • 移除 load_session_memory 里的幻影 注入会话摘要 日志——它声称的注入从未发生。
  • 新增 真实 INJECT 记录在 build_session_context（即实际进 prompt 的那一刻）。
  • 改写 prompt_load_overview 复用同一个装配器，逐段输出 session:pinned / session:recent / … 及各自真实 token，不再笼统报一段、不再展示未进 prompt 的来源。
