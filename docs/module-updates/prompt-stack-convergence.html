0 · 收敛目标

原则：不再继续新增特殊上下文槽，不再围绕 pinned / tools / attachments 做复杂特判。 每个 Agent 的差异应来自 Active Skill / Allowed Tools / Evidence 来源 / Output Schema， 而不是各自拼一套上下文。本批（A+B+G）落地"SOP 层 + 统一 assembler + 诚实可观测"三件， 为后续 event/artifact 收敛（C–F）打地基。

A统一 Agent SOP / Active Skill 层

把每个 Agent 的稳定执行规则从"散落在 system_prompt / progressive_sections 字符串"收敛成 结构化、可拆分、可测试、可独立 review 的 SOP——作为 Active Skill 注入，不含任何动态上下文。

  • render_sop() 确定性纯函数；改 SOP 不动 assembler 主链路、不影响其它 Agent

所有子 Agent 走同一套有序分层 prompt；差异只来自各层内容。新增 Project Guide 层， 把旧的"一坨 constitution"拆成 Active Skill（怎么做事）+ Tool Registry（能用什么）。

2 · 不变量 & 边界

  • Manager 仍是唯一编排者 + 唯一写者；子 Agent 只读上下文。
  • Diagnosis 仍客观：SOP 明确只基于结构化证据，不被闲聊污染。
  • 离线降级：无 key / 无 PROJECT_GUIDE.md / 无 vision 均优雅降级，链路永远通。
  • 保留兼容：assemble_prompt 旧参数别名、旧 pinned/progressive_sections 读取；未迁移 Router/Verifier/Retrieval/Judge/Strategist 回退 system_prompt。
  • 待后续：C–E（event/artifact 收敛 + Evidence 统一 + 跨轮附件召回）、F（Manager 轻量 routing context 接入 assembler）。

3 · 与 Claude Code 的差异

Claude Code 是单 Agent、append-only transcript——所有消息/工具结果都在它自己的上下文里，靠 compaction 收口。 LearnForge 是 Manager + 无状态 workers：每次子 agent 调用都重新装配一个固定 8 层 prompt，连续性靠显式 注入 Conversation State + 召回 Evidence 恢复。本批让"装配"统一、分层、可观测； 后续 C–F 会把 pinned/tools/attachments 进一步收敛为统一 event log + artifact retrieval，正是为了在无状态 worker 模型下补回 Claude Code 那种"它知道自己做过什么"的连续性。
