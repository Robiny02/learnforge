Mock 模块重构：状态机 → 智能规划2026-06

把僵硬的 LangGraph S1–S7 状态机换成手搓的 InterviewDirector；面试官人格全量接入开源 tech-interview-skill；模型分层 + 高质量解答。

一句话：mock 不再由 LangGraph 状态机 + checkpointer 的固定边驱动，改成每个 HTTP 调用跑一轮、状态存 SQLite、由 InterviewDirector 每步智能选下一个面试官动作。 与本项目 ManagerAgent.execute_dynamic 用手搓 ReAct 循环替代主图条件边的思路一致——"智能不在图里，在 Python 里"。 对外 MockInput / MockOutput 契约完全不变，所以 server / cli 一行没动。

为什么改

旧 mock 是 S1_INIT → S2_INTERVIEWER → S3_AWAIT(interrupt) → S4_JUDGE → S5_STRATEGIST → (loop | S6_COACH → S7_SETTLE) 的 LangGraph 子图，配 SqliteSaver 做 interrupt/resume。问题：

  • 僵硬：出题→等待→评分→Strategist 写死规则（"连续 2 轮 ≥4 升档"）→固定边路由，节奏由图拓扑决定，不会"看情况"。
  • 不会临场决策：不能根据回答质量决定是深挖、点破简历、纠错、还是收尾。
  • 面试官没人格：泛泛出题，不追问到底、不做简历诚信检测。

改前 vs 改后

改前（LangGraph 状态机）

  • 10 个节点 + 条件边的 mock_graph.py（422 行）
  • 路由写死在 StrategistAgent 的关键词 + 难度规则里
  • 状态靠 SqliteSaver checkpointer + interrupt()/Command(resume=) replay
  • 下一步去哪由图的边决定
  • 面试官出泛泛题，无简历诚信/双角色/分环节
  • 解答/提示只有 control.py 的确定性模板文案

改后（InterviewDirector 智能规划）

  • 无图。director.py 每轮选 move，mock_agent.py 一调用跑一轮
  • 路由由 Director.decide_next 决定：Haiku 路由 + 确定性兜底
  • 状态存 MockStateStore（SQLite 自愈表 + dict 兜底），"resume"=读回状态再跑一轮
  • 下一步去哪由 Director 看整场状态决定
  • 全量接入 tech-interview 人格：追问到底/简历诚信/双角色💡/三环节/评分 rubric
  • 解答/提示/纠错由 Interviewer.explain() 走强模型高质量生成

新引擎：每个调用 = 跑一轮

store.load(sid)→按输入分流→Judge 评分→Director.decide_next→执行 move→store.save
control_action / user_interrupt / user_answer / pending 四路分流 ｜ 无 LangGraph、无 interrupt/resume replay
agents/mock/mock_agent.py — answer()（精简）
state = self.store.load(sid)
if state is None or state.status in ("review","settled","escalated","expired"):
    return MockOutput(status="expired", ...)   # 优雅过期，不崩
if state.status == "paused": state.status = "active"  # 下一条消息即恢复
followup = self._run_turn(state, user_answer, user_interrupt, control_action)
self.store.save(state)        # 状态全量持久化（替代 checkpointer）
return self._to_output(state, followup=followup)

Director 的动作空间（借旧状态做动作）

每轮答完，Director 从受限动作空间里选一个；LLM(Haiku) 路由，解析失败/无 key → _fallback_move 确定性兜底（难度规则 + 环节推进 + 空转/收尾）。

ask 出新题/推进环节 followup 顺着回答深挖 probe 简历诚信点破 correct 答错→高质量纠正 raise / lower 调难度 switch_topic check_continue 空转→问继续/总结 summarize 收尾复盘 escalate 交回 Manager pause
Director 只选动作，不生成内容——生成交给 Interviewer（强模型）。这与 ManagerAgent.decide_next 选子 agent 的设计同构。 CORRECT 只在评分 confidence ≥ 0.5 时才触发，避免离线低置信打分让它每轮都"纠错"。
