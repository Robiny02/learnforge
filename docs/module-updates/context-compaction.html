会话级上下文压缩 Claude Code 式 compaction

把上下文压缩从「单次 prompt 组装时按 volatile budget 裁尾部」重构为 「每个 agent turn 结束后、按累计 session token 阈值触发」，并新增重要结果 pin 保护。

1 · 设计转向

✗ 旧机制（已撤回）

  • 触发点：每次 llm_structured() 组装 prompt 时
  • 粒度：单次调用级 —— 裁 retrieved + session volatile 尾部
  • 按固定 token 预算硬裁，user_input 永不裁
  • 每次调用都重算、重裁，无跨轮记忆
  • 问题：与"会话上下文增长"脱节；重复计算；无重要结果概念

✓ 新机制（Claude Code 式）

  • 触发点：每个 agent turn 结束后（record_turn）
  • 粒度：会话级 —— 统计整个 session context 累计 token
  • 占上下文上限 80% 才把最旧轮折叠进 summary
  • 压到 ~35%，但至少保留 MIN_RECENT 轮
  • 重要结果 pin：永不压缩、置顶注入
阈值不是绝对小数，而是「上下文上限的占用率」（Claude Code 语义）。早期版本曾用绝对值 6000（≈窗口 5%），几十轮就触发、过于频繁，已废弃。现按 CONTEXT_LIMIT_TOKENS （默认 = 模型窗口 128K）的百分比派生。memory/tokens.py（tiktoken 优先 + 字符估算降级） 负责统计 token；其余 prompt 组装回退为纯拼接。

2 · 阈值怎么来的

# 项目上下文 token 上限（默认 = 所用模型窗口；env LF_CONTEXT_LIMIT_TOKENS 可覆盖）
CONTEXT_LIMIT_TOKENS = 128000 # openai/gpt-4o-mini 窗口；换 claude-3.5-sonnet 设 200000

SESSION_COMPACTION_THRESHOLD_TOKENS = 128000 × 0.80 = 102400 # 占上限 80% → 触发
SESSION_COMPACTION_TARGET_TOKENS   = 128000 × 0.35 = 44800   # 压到 ~35%（30–40% 区间）

单轮 user/reply 各截 500 字符（≈中文 1k / 英文 250 tok）， 故 ~102K 约对应 近百轮对话才触发压缩、压到约 45 轮——日常对话几乎不触发， compaction 只在真正逼近上限时兜底，pinned + MIN_RECENT 兜住重要/最近内容。

6 · 触发逻辑（record_turn 核心）

orchestration/manager.py · record_turn()
# session context tokens（pinned 不可压 → 不计入触发，避免压不下去；它单独占注入预算）
def _ctx_tokens() -> int:
    t = count_tokens(summary)
    for r in rounds:
        t += count_tokens(r.get("user", "")) + count_tokens(r.get("reply", ""))
    return t

# 触发：本轮结束后 token 超阈（上限×80%）→ 折叠最旧轮直到 ≤TARGET（上限×35%，至少留 MIN_RECENT 轮）
if _ctx_tokens() > SESSION_COMPACTION_THRESHOLD_TOKENS:
    overflow = []
    while (_ctx_tokens() > SESSION_COMPACTION_TARGET_TOKENS
           and len(rounds) > SESSION_MIN_RECENT_ROUNDS):
        overflow.append(rounds.pop(0))      # FIFO：折叠最旧轮
    if overflow:
        fold_count += 1
        if LLM.available and fold_count % SESSION_RESUMMARIZE_EVERY == 0:
            summary = self._resummarize_session(summary, overflow)  # 周期性结构化全量重摘
        else:
            summary = 增量折叠(summary, overflow)[-800:]          # 离线纯增量、防膨胀

7 · 重要结果保护机制（pinned）

① 谁算"重要" — turn_is_important()

带引用的可核验答案
citations 非空		→ pin
诊断 / 规划 / 模拟面试的结构化产出
plan 命中 diagnosis / planning / mock		→ pin
简历诊断端点
server 显式 important=True		→ pin
纯闲聊 QA（无引用）→ 不 pin，随 compaction 折叠

② 怎么存与保护

  • 存进 active_task["pinned"] —— 复用既有 JSON 列，零 DDL 迁移、向后兼容
  • 永不参与 compaction、永不折叠进 summary
  • load_session_memory 渲染时 置顶全文注入：[重要结果·固定] …
  • 防膨胀：MAX_PINNED=8（FIFO 丢最旧）+ PIN_MAX_CHARS=500（单条截断）
  • 不计入触发阈值 —— pinned 不可压，计入会导致"压不下去"的死循环

8 · 测试与验证

tests/test_context_compaction.py（10 例，全离线）覆盖：

  • tokens 基元：空串=0、单调性、truncate_to_tokens 不超预算且带标记
  • 会话级触发：阈值调小后灌大内容 → summary 非空、recent < 灌入数
  • 阈值下不压：默认 ≈10 万（上限×80%）下两轮短内容 → 无摘要、原文全留
  • MIN_RECENT 下限：灌 10 轮仍 ≥ 2 轮原文
  • pin 保护：大量闲聊后重要结果仍在 pinned、渲染含 重要结果·固定
  • pin FIFO：超 cap 丢最旧、留最新
  • turn_is_important：citations / diagnosis / planning / mock → True；qa → False
