# OCR 与小红书噪声策略 v2

## 背景

小红书数据通常是按关键词和时间抓取，因此它不像随机网页那样充满完全无关内容。更真实的噪声包括：

1. 非计算机岗位面经：产品、运营、HR、销售、管培生；
2. 个人感受：焦虑、求好运、timeline、OC、被捞、秒挂；
3. 信息过短：只有“拷打项目”“手撕没写出来”，没有题目；
4. 评论区混合：部分有技术补充，部分是求模板、求部门；
5. 图片 OCR 混合：截图中有技术题，也可能有状态、日程、个人感受。

## 推荐处理

不要在切片前把噪声全部删除。建议先做 block 级分类：

- technical_core：明确技术问题、项目追问、算法题；
- useful_context：面试轮次、岗位、时间线中和判断质量有关的信息；
- career_noise：个人感受、求好运、timeline；
- off_topic_job：非技术岗位面经；
- useful_ocr：图片 OCR 中的技术题；
- irrelevant_ocr：图片 OCR 中的个人感受、日程、奶茶、穿搭；
- ad_or_promo：广告、引流、推荐阅读；
- empty_or_garbled：空 OCR、乱码、纯 emoji。

## 重要原则

- 有技术关键词的 OCR 先保留，不要误删。
- 非技术岗位面经不要直接丢弃，应该作为 off-topic 样本测试检索降权能力。
- 个人感受可以保留为低权重信息，但不应该污染技术 chunk。
- 评论区需要拆分，因为它可能同时包含有用补充和无关互动。
